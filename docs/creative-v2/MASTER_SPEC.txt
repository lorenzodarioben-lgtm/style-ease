## 01 — Non-negotiable observed defects: begin by reproducing them

These are verified from the actual branch source and repository screenshots. Locate the current equivalents, document whether the defects remain, and prove each fix:

**A. Collections and Editorial are literally duplicated.** In `internal/web/server.go`, `/collections` and `/editorial` currently resolve to the same `views.Collections(vm)` template. `/collections/{slug}` and `/editorial/{slug}` also share the `views.Story(vm)` implementation. This must stop. They need fundamentally different data, information architecture, page templates, visual compositions, interactions and calls to action. Do not create two skins for the same listing.

**B. Image composition is not art directed.** The shared `views/pages.templ` `Picture` helper accepts a product and loading flag; it does not accept focal metadata or usage context. The CSS applies `object-fit: cover`, landscape fixed-height `.story-image`, global filters, and largely hard-coded object positions such as `.story-image img { object-position: center 30%; }`. These produce arbitrary crops across desktop/mobile. The screenshots committed in `docs/screenshots/overhaul/` show the problem. This must be systematically corrected, not cosmetically hidden.

**C. Signature sliding-fill buttons disappeared.** Original `src/css/02-home-layout.css` contains a pseudo-element sliding across `.hero-cta`, `.add-to-cart`, `.add-to-cart-detail`, and `.checkout-btn`. The Go UI's `.button` in `assets/css/black-label.css` largely just changes colour and moves the arrow ~4px. Restore and greatly refine the original sliding-fill signature, adapted to the new design system. Keyboard focus must reveal an equivalent state.

**D. Original grayscale-to-colour transitions disappeared or were neutered.** Original `src/css/02-home-layout.css` hero/product styles transitioned from grayscale to colour. New campaign/story photos are often permanently grayscale; product cards only go from `saturate(.25)` to `.7`. Build an unmistakable but tasteful monochrome→true-colour image-reveal system on appropriately selected surfaces. Not every image needs full colour; the selective release of colour IS the dramatic point. Test it on hover, focus and touch alternatives.

**E. Brand identity looks generic and awkward.** The current mark (`templ Mark()`, `.monogram`, `assets/favicon.svg`) is a hastily assembled square-stroke S-like glyph. The header wordmark is generic. Replace it with a defensible, custom visual identity, not another little geometric doodle. Show real concept alternatives and assess at tiny and giant sizes.

**F. Motion language is nearly absent.** The page currently has a simple hero heading entrance, occasional zooms, arrow translations, and standard hover/background transitions. Create a cohesive motion system with memorable but quiet mechanics: directional masking, stagger, sliding fills, image saturation reveal, hover micro-architecture, thoughtful scroll entrances, refined menu/overlay states and feedback for cart, wishlist and Studio actions. Avoid scroll hijacking, forced waits and perpetual movements.

**G. Style Studio looks like a backend form.** The current empty `docs/screenshots/overhaul/studio-1440.png` has a large empty neutral panel and six conventional `<select>` elements. The underlying durable look system is impressive; its UX is not. Transform the surface into a visual styling atelier without discarding the working authoritative saving/ownership logic.

**H. Visual sameness everywhere.** The same neutral beige paper, oversized sans headings, repetitive card patterns and fixed image sections recur. Develop a compelling rhythm: ink/bone alternation, asymmetry, hero storytelling, varied image scales, expressive typography, quieter dense shopping surfaces, and intentional whitespace. The end product must still feel like ONE brand.

**I. Product catalogue copy and imagery are demo references, not verified SKU photographs.** Do not misrepresent them. Keep clear, non-repetitive disclosures, and do not create fictitious material, colour, sustainability, discount, rating, shipping or brand claims. An artful UI should not depend on dishonesty. Where exact product photos do not exist, use art-directed editorial images appropriately, with truthful labels.

## 03 — Brand north star: a genuinely original fashion house

Choose a design world: **STYLE EASE / BLACK LABEL — kinetic monochrome editorialism**. Keywords: architectural, bold, sensorial, unexpected, fashion-forward, tactile, directional, minimal but not empty, precise but not corporate, cinematic but not gimmicky.

Visual quality should approach carefully art-directed independent luxury fashion magazines and outstanding award-level ecommerce experiences. This is a benchmark of **craft**, not permission to copy another brand's site, product photography, trademarks or layouts. Avoid Shopify starter templates, generic SaaS dashboards, cookie-cutter UI kits, glassmorphism, purple gradients, randomly rounded cards, and stock-photo collage with no cohesive art direction.

Make the visual identity cohesive using:
- A beautiful custom wordmark and optional truly excellent secondary mark.
- Display typography with rich contrast between expressive editorial type and utility typography; intentional optical sizes, ligatures/kerning where appropriate, disciplined width/line breaking, typographic hierarchy, readable small text.
- Deep charcoal/ink, warm bone/ivory, graphite and one nuanced secondary tonal family, allowing source photography's TRUE colour to emerge through interaction. Keep gradients only where they solve a real compositional or legibility need.
- Rich modular editorial grids: full-bleed, off-grid, magazine spreads, asymmetric ratios, negative space, overlapping type only when legible, unexpectedly scaled image moments, strong alignment across sections.
- Distinctive reusable motion primitives, but not identical entrances on every component.
- Sharp image quality and meaningful, consistent photographic treatment; careful crop selection on every major image.
- Thoughtful navigation/footers and robust commerce controls with excellent hierarchy.

**Art direction needs visual choices.** Create `docs/creative-v2/CREATIVE_DIRECTION.md` explaining the final idea, audience, decisions, rejected generic options, typography, palettes, image treatment, layout rules, motion vocabulary and per-page differentiation. Include at least one actual rendered mood/composition contact sheet using appropriately licensed existing images, not invented claims. Use browser captures, not merely written descriptions.

### The wordmark challenge — mandatory three-way comparison

Design **at least three meaningfully different** original wordmark/identity concepts, such as: (1) custom high-fashion typographic ligature, (2) architectural grotesk with careful cut/spacing, (3) refined editorial serif/sans tension. Do not make three versions of the same angular S. Create actual SVG/CSS/HTML renderings and screenshot a comparison sheet at header size, square avatar size, light/dark surfaces and large footer treatment. Evaluate legibility, distinctiveness, optical spacing, mobile header fit, favicon clarity, and accessibility. Pick the strongest and explain why. Use properly licensed typefaces, self-hosted when practical. Do not distribute unlicensed font binaries.

An icon is NOT mandatory. If the best identity is just a beautiful typographic `STYLE EASE` wordmark, use that instead of forcing a bad monogram. Keep favicon legible at 16/32px and ensure the logo is not distorted or visually off-center. No generic bag, hanger, crown or “SE inside a circle” unless the form truly merits inclusion.

## 04 — Image laboratory: cropping, editorial assets and truthful merchandising

Treat every image as an art-direction problem. **Do not continue blindly applying `object-fit:cover` and one `object-position` to unrelated photographs.** First produce a real inventory of all campaign, collections, editorial, product, related and Studio images and where they appear.

Create `docs/creative-v2/IMAGE_AUDIT.md` and a machine-readable `assets/data/image-art-direction.json` or equivalent typed Go asset metadata. Per image/context record:
- source asset and provenance/licence, true pixel dimensions, orientation and file type;
- intended usage: campaign full bleed, collection cover, editorial portrait/landscape, product card, product detail, Studio tile, etc.;
- subject location and important content: face, entire garment, headroom, hands/feet, key silhouette, composition-safe text area;
- desktop/tablet/mobile focal anchors (e.g. percentages), allowed crop ratios and minimal visible subject bounds;
- whether a distinct mobile image or manually exported crop is required;
- image colour/grayscale treatment and intended colour-reveal state;
- responsive sources, intrinsic dimensions, loading priority, alt/caption requirements and graceful fallback.

**Important:** CSS `object-position` alone cannot rescue a portrait photo shoved into a very wide shallow box. For irreconcilable aspect ratios, choose a different licensed image, alter the layout, export an intentional art-directed crop, or use `<picture>` with genuinely different source crops. Never distort an image, cut off a subject's head/face/feet in a fashion hero without explicit artistic justification, crop away the product, or hide a problem under gradients. Prefer actual assets with sufficient resolution. Do not invent product angles or recolour photographed clothes to imply genuine listed colour variants.

Build a reusable responsive image component/helper with explicit **context-specific** art direction rather than product+eager only. It should support responsive art-direction sources, focal positioning, distinct intrinsic sizes, aspect-ratio choices, zoom safety, progressive enhancement, loading priority, sensible fallback and alt semantics. Keep layout shift low. Avoid putting heavy image processing on request paths; generate derivatives offline/build time with provenance.

Make before/after side-by-side comparison contact sheets for homepage hero, collection covers, editorial features, product grid and product details at **320, 390, 768, 1024, 1440 and 1920px**. For high-impact images also check DPR 2. Inspect actual photos visually. A successful audit has **zero obvious accidental face or garment amputations**, no stretched distortion, no blurry hero and no awkward text/photo collision. Mark each image pass/fail in the audit. If an asset is inherently unsuitable, replace it with an appropriately licensed asset and record the source. Do not use unknown watermarked stock photography.

Do not fill the repository with dozens of near-identical generated derivatives without reason; select a high-quality coherent image set. Avoid unnecessary transfer weight. Make interactive coloured reveals meaningful: grayscale is the editorial resting state, colour reveals can be full-saturation and beautiful when intentional.

## 05 — Motion grammar: resurrect the signature, then surpass it

Design the motion system BEFORE scattering CSS transitions. Define motion tokens for duration, easing, distance, stagger, opacity, clip/mask, image zoom, colour saturation, and feedback timing in `docs/creative-v2/MOTION_SPEC.md`.

Mandatory motion primitives:

**A. Signature sliding-fill CTA (non-negotiable).** Across hero, shop actions, product purchases, editorials and dialog actions, a pseudo-element or equivalent layer sweeps horizontally/diagonally across the button on hover/focus. It must have proper stacking, readable foreground contrast throughout transition, thoughtful direction, arrow/text choreography and variants for ink/bone/outline surfaces. Unlike the old crude `left:-100%` rule, implement consistent reusable architecture. Suggested hover timing 450–700ms with premium deceleration; interaction state must not cause layout shift. Disabled and processing states are distinct. Touch receives an immediate pressed/feedback state. Keyboard focus is fully supported.

**B. Monochrome-to-colour photographic reveals (non-negotiable).** At least the homepage collection imagery and primary catalogue/product-card system must visibly shift from elegant monochrome to genuine colour on hover/focus. A default `saturate(.25)`→`.7` is NOT enough. Animate `filter` deliberately; consider layered colour and grayscale images for more artful mask/wipe reveal where performant. Keep contrast/readability, responsive handling and no irreversible low-contrast text overlays. Do not force grayscale on every photo.

**C. Editorial image choreography.** Restrained mask/curtain reveals, coordinated scale settling and staggered caption entrance. One statement effect per section is better than six simultaneous effects. Scroll reveals must not block content if JavaScript fails or if content is immediately reached via deep link.

**D. Navigation.** Desktop underline/bar transitions with tasteful microinteraction; mobile navigation that opens with clear layered choreography, works without unexpected jumping, traps and restores focus correctly when modal, and is immediately usable under reduced motion.

**E. Product interaction.** Beautiful but fast image response, card emphasis, optional context-sensitive quick actions, variant selection, gallery thumbnail swap and full-image zoom, wishlist/save acknowledgement, add-to-bag feedback, and graceful loading/error states. State changes must be honest and server-validated.

**F. Style Studio.** Choosing a piece should produce deliberate visual arrival/replacement, reorder transitions where supported, selection feedback and total changes without long blocking animation. Save/reopen state should feel satisfying, with meaningful live announcement.

**G. Page navigation.** With server-rendered Go and HTMX history, implement *only* tasteful progressive page transitions if they preserve back/forward semantics, scroll restoration, focus movement, deep links and accessibility. Never hide route content behind asynchronous animation. CSS View Transitions API is optional with safe fallback, not an excuse to break navigation.

**H. Scrolling.** Implement selected IntersectionObserver-based entrances or CSS-native scroll-driven motion with graceful fallback. Prefer transform/opacity/masks over layout and paint-heavy properties. Absolutely no universal hijacked scrolling, giant cinematic loader, frozen scroll, perpetual marquee, mandatory audio, or pointer-following decoration that obstructs tasks. Optional tasteful ticker only if actually useful and motion-safe.

Every motion feature MUST have: pointer test, keyboard test, reduced-motion behaviour, touch fallback, graceful failure, acceptable frame rate, and no interaction blocking. Use `prefers-reduced-motion: reduce` to remove nonessential animation while retaining meaningful state changes. Do not add a large animation library by default; if one is unavoidable, prove its value and show bundle/performance effect.

Record short actual Playwright videos and animated-hover before/after captures: hero CTA sweep, product image colour reveal, nav/menu, one scroll reveal, product gallery, Studio selection and save. No claim that an animation is restored unless its footage actually shows it working. Where tests cannot judge beauty, inspect recordings manually and write observations.

## 06 — Separate Collections and Editorial for real

This is an **information architecture and content model** correction, not a CSS tweak. Remove route aliasing and implement independent handlers/views and appropriately distinct data structures. Keep existing collection slugs/bookmarks functioning, and decide carefully whether existing `/editorial/{slug}` links redirect to a valid new article or preserve a compatibility path; document the decision. Never knowingly serve the exact same DOM/template under two supposedly different top-level destinations.

### Collections = SHOP THE EDIT

Collections are commercial curation, not articles. Design a compelling **collection hub**: image-led campaign covers of varied proportions; meaningful categories/edits; strong selection counts and navigational affordance; cinematic but fast card/image hover; typography that frames merchandise; curated product sets with accurate data; shop-this-edit and refine actions; mobile layouts that show what is being sold. Individual collection pages should be beautifully merchandised with a distinct campaign panel, related collection navigation, clear product grid, sorting/filter state and quick-shop flows. Use data-driven collection hero assets distinct from editorial story leads when possible.

### Editorial = READ THE STORY

Editorial is a fashion publication. Create an independent **journal/editorial landing page** with its own hero, issue/chapter hierarchy, asymmetrical magazine grid, visual essays, readable dek/byline/date only when factually justified, art-directed typography, interspersed portrait and landscape imagery, pull quotes when authored, and deliberate cinematic scroll reveals. Stories must have real narrative structure and several sections, not generic filler or product descriptions disguised as articles. Provide contextual shop-the-story references to existing demo products, properly labelled. The editorial reading experience should have its own table of contents or chapter flow when appropriate; reading should never feel like filtering a product list.

Editorial content can be transparently creative/fictional rather than pretending real designers were interviewed. Do not invent journalists, photographers, endorsements, reviews or product facts. Create 2–3 **substantive and visually different** editorial stories, with intentional cover images and layouts, not three templated clones. Editorial assets must be appropriate for narrative crops, not automatically selected as the first product in a category.

**Acceptance test:** a first-time visitor should distinguish Collections from Editorial within one screen, without looking at the URL. Build independent templates and browser tests verifying meaningful structural/content differences, distinct metadata/title and navigation active states. Screenshot both at desktop and mobile side by side and critique the difference. If they still look or behave like twins, redesign one again.

**Performance budgets:** protect the previously documented fast baseline (home local mobile LCP roughly 2.3s, 14.82 KiB gzip authored+vendor JS combined, and 8.94 KiB gzip CSS in the prior PR's reported environment). New animation cannot be excused by “premium means heavy.” Aim for local mobile LCP <=2.5s, CLS <=0.1, and visibly smooth animations; report actual environment, repetitions and variability. Permit a justified increase in client JS to at most **45 KiB gzip** and CSS to at most **30 KiB gzip**, unless the measurements prove a superior tradeoff and the report identifies it transparently. Avoid replacing the tiny app with a large SPA, autoplay HD video, huge canvas effects or many blocking animation dependencies. Optimize key image loading without gaming metrics by hiding images or removing creative content.

Do not fake measurement results. If tests fail, fix the app or explicitly list unresolved issues. A test suite pass is required but **never sufficient** for creative signoff.

## 12 — Milestone sequence with hard gates

Work deliberately in vertical slices. Do not spend the whole budget writing plans or perfecting a single homepage while other routes remain generic.

**M0: Baseline, protection, evidence** — Record parent SHA, current tests and screenshots, functional routes, benchmark, and crop/interaction failures. Create safe child branch and handoff. No production changes.

**M1: Brand concepts + design system** — Render and compare three identities; choose one. Build design tokens, typography and motion primitives; prototype primary CTA and colour-reveal to visibly prove they work. Gate: first-fold proof on mobile/desktop plus actual hover/focus evidence.

**M2: Image lab + editorial assets** — Audit images; establish art-direction metadata; repair all major crop defects with contextual sources and CSS. Gate: before/after crop contact sheets across breakpoint matrix, no obvious accidental subject cropping.

**M3: Collections and Editorial split** — Independent route handlers, data/templates, distinct art direction and actual content. Gate: screenshot A/B comparison and tests showing these are different products, not route aliases.

**M4: Homepage / navigation / footer** — Recompose for true visual impact; refine brand, choreograph hero, introduce high-quality image moments and compelling exploration. Gate: mobile and desktop hero critically reviewed; first fold better than prior, no lost UX paths.

**M5: Shop + product + commerce polish** — Great cards, interactions, honest product imagery, gallery/zoom as assets allow; cart, wishlist, comparison, checkout, receipts and state surfaces consistent. Gate: actual purchase/variant/keyboard flows and full screenshots.

**M6: Style Studio atelier** — Replace form-first layout with image-first composition workspace while keeping Go/PG saving/ownership semantics. Gate: empty, selected, saved and reopened states dramatically improved; mobile and keyboard users can perform the core tasks.

**M7: Hardening + five critiques + final artefacts** — Responsive, interaction recordings, performance, accessibility, screenshots, docs, tests, fixes, honest final scorecard. Gate: all meaningful P0 issues resolved, core flows passing, no severe crop regressions, no duplicate sections, no broken active states.

If running out of context/time: prioritize completion of M1–M5 and preserve a stable functional app. Do not leave half-finished migration code or incomplete experiences. Record genuinely incomplete M6/M7 work in handoff. Continue proactively without requiring check-ins for normal design decisions. Do not falsely declare completion if unfinished.

## 14 — Explicit acceptance / refusal criteria

**FAIL immediately if any of these remain:**
- `/collections` and `/editorial` display identical content/templates with token heading differences.

- The original colour-reveal signature is absent or only changes saturation from 25% to 70%.

- Static screenshot tests or Lighthouse scores are used as the only justification of creative quality.
- Any backend/auth/session/payment/stock safety feature is silently weakened, original data IDs lost or tests removed to appear green.

**PASS requires:**

- Deep and unmistakable structural difference between Collections and Editorial.

- Every commerce route polished, mobile-first, keyboard-usable and functionally verified.
- Documented critique-and-revise evidence, passing core engineering checks, honest limits.

## 15 — Work ethic and stopping rules

Do not ask for approval on ordinary compositional choices; make informed decisions, render them, critique them, improve them. Don't respond with only a list of recommendations. **Actually edit the code, run the app, and demonstrate the result.** Prioritize quality over churn. If a layout is merely “fine,” do another thoughtful pass. If the crop is poor, fix the source, focal point or composition, not just the border radius. If Editorial feels like Collections, rebuild the page structure. If the logo is weak, reject it and test a better concept. If the animation is too subtle to notice, refine the effect; if it is distracting, dial it back. Strong fashion design is controlled contrast, not chaos.

Keep the existing Go backend as the reliable foundation. Make the visual output **dramatically** better than the current Black Label branch, while preserving extraordinary reliability. Only stop when you've either met the explicit acceptance criteria with real evidence or exhausted the available session budget and preserved a clear, honest handoff.

**START NOW:** verify the actual branch and runtime; capture the currently broken routes; create the safety branch; implement the wordmark concepts and restored signature button/image motion; then proceed through the milestones without waiting for further prompts.
